# 2026-09-07 · 打包分发流水线

## 本次做了什么

- 落位打包三件套：
  - `packaging/app.py`：PyInstaller 入口。冻结环境必须传 app 对象给 uvicorn（字符串模块路径依赖 importlib 解析，打包后不可用）
  - `packaging/app.spec`：onedir 方案；前端 dist 不打进包，外置于 exe 同级，由 main.py 挂载
  - `scripts/build_release.ps1`：一键流水线，6 步——前端构建 → PyInstaller → 组装 voice-system/（app.exe 运行时 + web/dist + start.bat + 使用说明.txt）→ zip → 清理中间产物（release/pyinstaller、release/_build）
- `server/main.py`：新增 `_resolve_web_dist()`。`sys.frozen` 时以 exe 同级 `web/dist` 为准（`__file__` 在 `_internal` 里反推不出来），开发态不变
- 依赖与忽略：`pyinstaller>=6.10` 入 dev 组；`.gitignore` 增 `release/`、`build/`
- 脚本健壮性（实测踩坑后加固）：
  - node 定位：`NODE_EXE` 环境变量覆盖 > PATH > Program Files / LOCALAPPDATA / hermes / WorkBuddy 托管目录（版本号最大者）回退
  - npm：优先 node 同目录 `npm.cmd`；若其无法启动（`LASTEXITCODE` 为 null）自动降级 `node + npm-cli.js`
- 验证：用户在系统终端手动运行脚本，打包成功、冒烟通过（本机 assistant 沙盒拉不起原生 exe，故执行一律交用户）

## 遗留问题与坑

- **沙盒限制**：WorkBuddy 内置 PowerShell 会话无法拉起任何原生 exe（静默失败、`LASTEXITCODE` 为 null），只有 cmdlet 可用；bash 拉起原生 exe 正常但被禁止调 powershell.exe。→ 构建/打包类命令一律给步骤让用户手动跑
- npm.cmd 本质是批处理，受限终端拉不起；`node + npm-cli.js` 是万能兜底（标准 npm 安装均有该文件）
- PyInstaller 打包后中文控制台输出在部分捕获环境下乱码——仅显示层，不影响执行
- 分发包不含语音克隆子服务及其模型权重（独立分发，见使用说明）
