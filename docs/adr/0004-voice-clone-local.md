# ADR 0004：语音克隆采用本地 GPT-SoVITS 并封装为独立进程

- **状态**：已接受
- **日期**：2026-09-02
- **相关**：PLAN.md 阶段三 3.1、AGENT.md 第 10 节

## 背景

题目表要求拓展功能至少实现一项。已确定做语音克隆。候选路线有本地部署开源模型与调用云端 API 两类。

## 决策

**纯本地部署 GPT-SoVITS，封装为独立进程与独立 Python 环境，通过 HTTP 与主干通信。**
不使用云端 API。

## 理由

1. **本地部署是课程项目的正确形态**：无网络依赖、无限额与隐私顾虑、答辩时可控可复现，也能体现工程能力。
2. **中文效果最好。** GPT-SoVITS 在中文少样本克隆上的自然度与相似度目前是开源第一梯队，且社区资料丰富。
3. **硬件条件满足。** 本机 RTX 4060 Laptop / 8GB 显存，推理完全够用。

## 独立进程隔离的必要性

GPT-SoVITS 依赖 PyTorch + CUDA 及数 GB 模型权重，是**唯一可能拖垮整个项目的模块**。隔离带来三点保障：

- 依赖污染不扩散到主干环境，主干 `uv sync` 永远干净快速
- 子服务崩溃不影响基础功能演示
- 可独立启停，开发基础功能时不必加载模型

## 备选方案

| 方案 | 优点 | 未选原因 |
|---|---|---|
| 云端 API（CosyVoice / Fish Audio 等） | 零环境成本，接入快 | 依赖网络与额度，答辩存在不确定性，体现不了工程能力 |
| CosyVoice2 | 阿里官方维护，推理快 | 中文社区资料少于 GPT-SoVITS，排障成本更高 |
| OpenVoice v2 / XTTS-v2 | 多语言强 | 中文自然度弱于 GPT-SoVITS |

## 风险与对策

| 风险 | 对策 |
|---|---|
| CUDA / PyTorch 环境配置失败 | 独立 venv 逐步验证；先跑通官方推理脚本再接入 HTTP 服务 |
| 模型权重数 GB 入库 | `.gitignore` 排除 `models/`，统一走 `scripts/download_models.py` |
| 显存不足 | 使用官方提供的量化/半精度推理配置 |
| 合成耗时过长影响演示 | 提前预热模型，前端展示进度与异步任务状态 |

**降级预案**：主干侧 `TTSProvider` 抽象接口预留云端实现插槽。若本地方案在结题前两周仍未跑通，可在不改动主干与前端的前提下接入云端实现。当前不实现，只留接口。

## 后果

- 需维护第二套 Python 环境与依赖清单（`services/clone/requirements.txt`）。
- 需在 `AGENT.md` 注明子服务的独立启动方式。
