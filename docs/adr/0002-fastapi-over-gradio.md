# ADR 0002：后端框架选 FastAPI，不用 Gradio / Streamlit

- **状态**：已接受
- **日期**：2026-09-02
- **相关**：AGENT.md 第 2 节、第 7 节

## 背景

需要为 Python 后端选择一个对外暴露能力的方式。团队多人并行开发、跨多个 session，接口契约的稳定性比开发速度更关键。

## 决策

**使用 FastAPI + Pydantic v2 + uvicorn。** 前端为独立工程，通过 HTTP 与 WebSocket 通信。

## 理由

1. **自动 OpenAPI 文档就是活的接口契约。** 任何人打开 `/docs` 就能看到全部接口与字段定义，不用来回问人。这对多人多 session 协作是决定性优势。
2. **Pydantic 模型三重复用**：请求校验、响应序列化、前端动态表单的 JSON Schema 生成源。
3. **原生 WebSocket**，满足录音电平与频谱的实时推送。
4. **逻辑与界面彻底解耦**，避免调试 GUI 时牵连算法。

## 备选方案

| 方案 | 优点 | 未选原因 |
|---|---|---|
| Gradio | 几行代码出界面，Python 生态亲缘性高 | UI 与逻辑焊死，正是本项目要避免的情况；定制能力弱，难满足「界面友好」要求 |
| Streamlit | 数据应用快速成型 | 无状态模型不适合音频会话；不支持 WebSocket 实时推送 |
| Flask | 轻量、生态成熟 | 无内置校验与文档，需要额外引入 marshmallow + flasgger，拼装后等价于 FastAPI |

## 后果

- 需要自己写前端（已在 ADR 0003 中决定用 Vue 3）。
- 团队成员需理解 REST 与 Pydantic 基本概念，学习成本很低。
